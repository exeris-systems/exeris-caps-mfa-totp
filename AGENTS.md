# exeris-caps-mfa-totp

Operating contract for AI agents working in this repository.

## 1. Mission and scope

`exeris-caps-mfa-totp` is a single-module Exeris capability (Layer 5 — Domain primitive (identity)). It provides `TotpFactorRegistry`, `TotpVerifier`, `RecoveryCodes`, `MfaChallenge`. Licence: `commercial` — Exeris Commercial License 1.1, source-available
(ADR-023). It is a proof of concept built against `exeris-kernel` 0.13.0-SNAPSHOT; `README.md` describes
what it does and does not do.

## 2. Operating contract and boundaries

- **The cap-tier Wall (ADR-055), build-enforced.** `eu.exeris.caps.mfatotp.api` is the cross-cap surface and `eu.exeris.caps.mfatotp.internal` is private.
  The package root `eu.exeris.caps.mfatotp` is load-bearing: the guard derives the cap's own name
  (`mfatotp`) from the segment after `eu.exeris.caps.`. Never put an `internal` type in a public
  signature.
- **No host runtime (ADR-006).** No `org.springframework.*`, `jakarta.servlet.*`, `io.netty.*` or
  `reactor.*` import, in main or test sources.
- **Declarations.** The `@CapabilityModule` class carries the whole contract. Do not add a speculative
  `@Requires`: it is an edge in every SKU's composition graph. While the capability is unreleased every
  `@Provides` stays at `version = "0.1.0"` and every `@Requires` on an unreleased contract at
  `[0.1.0,0.2.0)` (`standards/capability-conventions.md` rule 9); a breaking change does not bump a
  version and is stated as `breaking (ADR-099)` in the change's Compatibility impact line.
- **The committed manifest.** `src/main/generated/java/cap-manifest.json` is tracked and regenerated by
  the build into `src/`. A declaration change commits the regenerated manifest with it.
- **Entitlement.** The cap registers an `EntitlementRequirement` (in `META-INF/services/eu.exeris.kernel.spi.contract.EntitlementRequirement`) whose capability id is `exeris-caps-mfa-totp`, its artifactId. Keep the id equal to the artifactId (ADR-089).
- **JDK 25, no preview.** `maven.compiler.release` stays 25; no `--enable-preview` in any scope.
- **No secret in source, none at rest in the clear (ADR-099 obligation 9).** The pepper that keys recovery-code
  and challenge-token hashes and the key ring that seals TOTP secrets are required configuration with no
  default; the module fails at construction without them. A stored secret that is not a sealed envelope is
  refused, never read as plaintext.
- **Tests.** JUnit 5 and AssertJ only; no mocking framework. `PostgresMfaRepositoryLiveIT` runs against a real
  PostgreSQL when `EXERIS_TEST_PG_URL`, `EXERIS_TEST_PG_USER` and `EXERIS_TEST_PG_PASSWORD` are set, and is
  skipped otherwise.
- **Safety.** Do not push, tag, publish or change repository settings unless the user asks. The vendored
  bundle policy `bundle:agent-safety-and-autonomy` applies.

## 4. `.agents/` discovery

- `.agents/manifest.yaml` — imports the organisation bundle `exeris-agents`, pinned by version, commit
  and digest.
- `.agents/vendor/exeris-agents-2.1.0/` — the vendored bundle: policies, base schemas and the hook
  dispatcher. Never edit it in place; bumping it means re-vendoring.

This repository authors no profiles, skills, workflows or hooks of its own.

## 5. Verification and reporting

```bash
mvn compile -Dexeris.codegen.skip=true   # pass 1 — seed capability metadata
mvn verify                               # pass 2 — generate, validate the graph, scan the Wall
git status --porcelain                   # must be empty: the committed manifest matches the build
```

The build log must show `Cap-tier Wall clean` with `own cap(s): [mfatotp]`. Report what ran and its
result; do not claim a check that was not run.
